---
title: Providers
description: Model strings, API key variables and base URL variables for every provider RouteHub supports
---

Prefix the model with its provider, as in `groq/llama-3.3-70b-versatile` or `openrouter/anthropic/claude-sonnet-4.6`. RouteHub reads the key from `api_key=` or the first set variable in the key column, and the base URL from `api_base=` (or `base_url=`) or the base URL column.

<Note>
  Claude is called through Anthropic's native Messages API rather than its OpenAI-compatible endpoint, which drops prompt caching, thinking output and cached-token usage. RouteHub translates the request and returns a standard `ChatCompletion`.
</Note>

## Bare model names

These prefixes need no provider:

| Prefix | Provider |
|---|---|
| `gpt-`, `o1`, `o3`, `o4`, `chatgpt-`, `codex-`, `text-embedding-`, `davinci`, `babbage`, `omni-moderation` | OpenAI |
| `claude-` | Anthropic |
| `gemini-`, `gemma-` | Gemini |
| `grok-` | xAI |
| `deepseek-` | DeepSeek |
| `mistral-`, `codestral`, `magistral-`, `ministral-`, `pixtral-`, `devstral-` | Mistral |
| `command-` | Cohere |

Any other bare name raises `BadRequestError` before a request is sent, unless you pass `api_base=`. Then RouteHub sends it to that server as `openai_like`. You can also set the provider for an unprefixed name with `custom_llm_provider=`.

## Check a model string

`get_llm_provider` resolves a model string without sending anything. It returns `(model, provider, api_key, api_base)`:

```python
import routehub

model, provider, api_key, api_base = routehub.get_llm_provider(
    "groq/llama-3.3-70b-versatile"
)
print(model, provider)  # llama-3.3-70b-versatile groq
```

## Provider notes

<AccordionGroup>
  <Accordion title="Azure OpenAI">
    Azure needs an API version as well as a key and endpoint. Pass `api_version=`, or set `AZURE_API_VERSION` or `OPENAI_API_VERSION`.

    ```python
    response = routehub.completion(
        model="azure/my-gpt-deployment",
        messages=messages,
        api_version="2024-10-21",
    )
    ```
  </Accordion>

  <Accordion title="Local servers: Ollama, LM Studio and vLLM">
    Ollama defaults to `http://localhost:11434/v1` and LM Studio to `http://localhost:1234/v1`. RouteHub appends `/v1` to `OLLAMA_API_BASE` when it is missing. vLLM and `openai_like` have no default base URL, so set the variable or pass `api_base=`.

    Local servers get a placeholder key when none is set: `ollama`, `lm-studio`, or `EMPTY` for vLLM and `openai_like`.

    ```python
    routehub.completion(model="ollama/llama3", messages=messages)
    routehub.completion(
        model="hosted_vllm/meta-llama/Llama-3.3-70B-Instruct",
        messages=messages,
        api_base="http://gpu-box:8000/v1",
    )
    ```
  </Accordion>

  <Accordion title="Any OpenAI-compatible server">
    Pass `api_base=` with any model name to call a server that implements the OpenAI chat API:

    ```python
    routehub.completion(
        model="my-internal-model",
        messages=messages,
        api_base="https://llm.internal.example.com/v1",
        api_key="sk-internal",
    )
    ```
  </Accordion>

  <Accordion title="litellm provider aliases">
    These litellm prefixes are accepted and mapped: `together` to `together_ai`, `fireworks` to `fireworks_ai`, `nvidia` to `nvidia_nim`, `google` and `google_ai_studio` to `gemini`, `x-ai` to `xai`, `vllm` to `hosted_vllm`, `custom_openai` to `openai_like`, `cohere_chat` to `cohere`, and `text-completion-openai` to `openai`.
  </Accordion>
</AccordionGroup>
